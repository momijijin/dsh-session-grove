Every file has the same 385 top-level keys and the same `{placeholder}` set as
`en.json`. The test suite fails if keys, placeholders or non-empty values drift.
46 of those keys are the `profiles.*` namespace (switcher, switch preview,
recovery, save-as and management dialogs); 54 keys were added by the
`0.4.0-beta.62` group-archive batch (menus, dialogs including the archive
confirm opt-out, drag reasons, toasts, empty states and the second
view-options tri-state). The `dev` tree now carries all
385 keys; the published `0.4.0-beta.60` package carries 331 and the previous
`0.4.0-beta.59` package had 286.

13 keys are CLDR plural objects (`one/other`, with `few/many/zero/two` added per
language where the locale requires them); the parity test compares the exact
category sets. `search.hiddenInArchived` and `search.hiddenOutsideArchived` are
the two new plural keys in this batch.

## Group archive

The group-archive batch adds one independent tri-state and the copy around it;
it never reuses the session-archive strings:

- view options: `archive.section.sessions` / `archive.section.groups` title the
  two segments; `archive.group.hidden|all|only` are the group rows (the session
  rows keep `archive.hidden|all|only`);
- menu/dialog/drag/toast/empty/search keys: `group.archivedLocked`,
  `group.containsArchived`, `group.archive`/`group.unarchive`,
  `menu.groupArchivedLocked`, `menu.groupContainsArchivedLocked`,
  `menu.sessionStructuralLocked`, `menu.groupPositionLocked`,
  `drag.archivedContainer`, `drag.archivedDestination`, `drag.archivedSource`,
  `drag.archivedSourceSubtree`, `drag.archivedAnchor`, `drag.dropRejected`,
  `dialog.archiveGroup*`, `dialog.archiveFrozen`, `dialog.destinationArchived`,
  `toast.groupArchived*`, `toast.showArchivedGroups`, `toast.showAllGroups`,
  `toast.createdInvisible`, `toast.movedInvisible`, `empty.archivedHidden*`,
  `empty.onlyNoArchived*`, `banner.archive-frozen`, `search.hidden*`,
  `search.showArchivedGroups`, `search.showAllGroups`;
- `profiles.preview.archiveChanged` flags archive-state differences in the
  switch preview.

All keys exist in the 19 packaged dictionaries with matching placeholders and
plural categories; structural parity is enforced by the unit tests. Runtime
copy review of the new group-archive surfaces is still pending (see
[TEST-MATRIX.md](TEST-MATRIX.md)).

## Client module layout

`src/client/locale.js` is a thin compatibility facade over:

```text
i18n/resources.js       locale JSON imports + dictionary registry
i18n/locale-id.js       base-language normalization + host/document resolution
i18n/message-format.js  CLDR plural selection + {placeholder} interpolation
i18n/translator.js      dictionary selection + createTranslator
i18n/direction.js       RTL detection + root direction for the plugin
i18n/date-format.js     absolute Date formatting (UI gets it via runtime bridge)
```

UI components only receive the translator function; they do not import locale
JSON or inspect plural categories. `tests/client/i18n-architecture.test.js`
enforces this boundary.

## Resolution

```text
Host locale snapshot (active/id)
→ document.documentElement.lang
→ navigator.languages / navigator.language
→ en
```

The selected id is normalized to its base language:

```text
ja-JP → ja
zh-Hant → zh-Hant
pt-BR → pt
unknown → en
```

Unsupported languages fall back to English, never to Chinese.

## Profiles

The 46 `profiles.*` keys cover the header chevron, the profile popover, the
switch preview (summary, group/session sections, stale and truncation copy),
recovery, save-as and the manage/rename/archive dialogs. They exist in all 19
dictionaries with matching placeholders and plural categories; structural
parity is enforced by the same unit tests as every other key.

`profiles.counts` uses one CLDR plural template for the group and session counts
in a row. Languages whose noun changes with the counted object can therefore
read approximately (for example English "1 sessions"). Splitting it into
separate `countsGroups` / `countsSessions` keys remains deferred.

## Host integration

The plugin registers all packaged dictionaries with the host locale service.
It does **not** call `addLanguage` and does not add a language picker. The host
or a third-party language pack owns the language catalog: when such a pack
activates `ja`, `ko` or another packaged language, the plugin switches
automatically.

## Known limits

- Arabic is the only packaged RTL language. Root `dir`, core list/header/dialog
  styling, menu/dialog viewport bounds and the settings-panel direction are
  covered; the profile popover/preview bounds and direction were exercised by
  the 2026-11-09 all-locale run. Exhaustive drag/resize geometry and every icon
  are not.
- `he`, `fa` and `ur` are not packaged.
- ru/hi/ar narrow-sidebar screenshots cover a 264px-min sidebar (252px content width after borders); header title ellipsis is expected and exposes full text via tooltip.
- Only English has the default full A+; Japanese has the onboarding fixture;
  all 19 packaged dictionaries have header/dialog/group-menu/settings smoke
  coverage through `.61`; the `.62` 385-key dictionaries still need the manual
  all-locales re-run.
- `archive.label` is still packaged in all 19 dictionaries but is no longer
  referenced after the view-options popover was split into two labelled
  segments. Removing it would change the 385-key parity count, so it is kept
  for now; this is a resource-only dead key, not a UI regression.
