# Localization

## Packaged languages

| Base language | File | Notes |
|---|---|---|
| `en` | `locale/en.json` | fallback language |
| `zh` | `locale/zh.json` | Simplified Chinese |
| `ja` | `locale/ja.json` | Japanese |
| `ko` | `locale/ko.json` | Korean |
| `de` | `locale/de.json` | German |
| `fr` | `locale/fr.json` | French |
| `es` | `locale/es.json` | neutral Spanish |
| `pt` | `locale/pt.json` | Brazilian Portuguese |
| `it` | `locale/it.json` | Italian |
| `nl` | `locale/nl.json` | Dutch |

Every file has the same 288 top-level keys and the same `{placeholder}` set as
`en.json`. The test suite fails if keys, placeholders or non-empty values drift.

## Resolution

```text
Host locale snapshot (active/id)
→ document.documentElement.lang
→ navigator.languages / navigator.language
→ en
```

The selected id is normalized to its base language:

```text
ja-JP → ja
zh-Hant → zh
pt-BR → pt
unknown → en
```

Unsupported languages fall back to English, never to Chinese.

## Host integration

The plugin registers all packaged dictionaries with the host locale service.
It does **not** call `addLanguage` and does not add a language picker. The host
or a third-party language pack owns the language catalog: when such a pack
activates `ja`, `ko` or another packaged language, the plugin switches
automatically.

## Known limits

- Count strings (`{n} sessions`, `{n} min ago`, …) do not have plural variants
  yet; languages with richer plural rules need a later `Intl.PluralRules`
  phase.
- RTL languages (`ar`, `he`, …) are not supported yet; the layout uses physical
  left/right CSS.
- Language-pack activation is not yet covered by an isolated A+ fixture; current
  tests exercise the resolver and dictionary selection at unit level.
