## Text truncation and degradation (0.4.0-beta.64)

The narrow-viewport batch adds **no copy and no keys**: the same 397 keys in the
19 dictionaries are reused, and every rule below is CSS/geometry, so all locales
inherit it without translation work.

- **Single-line labels ellipsize and keep the full copy in `title`.** Menu rows
  (`span.dsg-menu-item-label`; the row keeps `title`, a locked row keeps its
  disabled reason), running group headers (`.dsg-running-group-label`), running
  items (`.dsg-running-item-title`, the button carries `title`), view-option
  rows (`.dsg-view-option-label`), and profile rows
  (`.dsg-profile-item-label`) all use `overflow: hidden; text-overflow:
  ellipsis; white-space: nowrap; min-width: 0`. A long German/Russian label or
  a user-supplied name therefore cannot wrap and change row heights or the
  popover's shape.
- **The header title is hidden as a whole, not ellipsized.** When the usable
  width of `.dsg-header-title` drops below 42px (24px chevron + inline gap
  subtracted; the compact header uses the 2px gap) the root gets
  `data-title-collapsed="true"` and `[data-title-collapsed="true"]
  .dsg-header-label` is `display: none`; the label returns from 50px, an 8px
  hysteresis band so it cannot flicker. The measurement source is the wrapper,
  never the label it hides (a hidden label reads 0 and would lock itself away).
  The wrapper keeps `title` (`view.title`) and the profile chevron keeps its
  `aria-label`/`title`, so the text stays available to hover and assistive
  technology while the label is not painted.
- **Explanatory copy wraps instead of truncating.** `status.hint` relies on
  normal wrapping (`.dsg-status-hint` does not set `overflow-wrap`), while
  `about.scope` is backed by `.dsg-view-options-scope`'s `overflow-wrap:
  anywhere` (`.dsg-view-options-hint` sets it too). Both live in panels whose
  height the floating-panel controller caps to the space left around the
  trigger and that scroll with `overflow-y: auto`, so a long translation is
  never hidden. Only single-line labels are truncated, and only when the locale
  or the user's data really overflows.
- Menu boxes cap at `min(360px, 100vw - 16px)` with `box-sizing: border-box`
  and at the space left below the anchor; rows keep the 30px height, so a long
  label ellipsizes instead of making the menu taller.

## Client module layout

`src/client/locale.js` is a thin compatibility facade over:

```text
i18n/resources.js       locale JSON imports + dictionary registry
i18n/locale-id.js       base-language normalization + host/document resolution
i18n/message-format.js  CLDR plural selection + {placeholder} interpolation
i18n/translator.js      dictionary selection + createTranslator
i18n/direction.js       RTL detection + root direction for the plugin
i18n/date-format.js     absolute Date formatting (UI gets it via runtime bridge)
```

UI components only receive the translator function; they do not import locale
JSON or inspect plural categories. `tests/client/i18n-architecture.test.js`
enforces this boundary.

## Resolution

```text
Host locale snapshot (active/id)
→ document.documentElement.lang
→ navigator.languages / navigator.language
→ en
```

The selected id is normalized to its base language:

```text
ja-JP → ja
zh-Hant → zh-Hant
pt-BR → pt
unknown → en
```

Unsupported languages fall back to English, never to Chinese.

## Profiles

The 46 `profiles.*` keys cover the header chevron, the profile popover, the
switch preview (summary, group/session sections, stale and truncation copy),
recovery, save-as and the manage/rename/archive dialogs. They exist in all 19
dictionaries with matching placeholders and plural categories; structural
parity is enforced by the same unit tests as every other key.

`profiles.counts` uses one CLDR plural template for the group and session counts
in a row. Languages whose noun changes with the counted object can therefore
read approximately (for example English "1 sessions"). Splitting it into
separate `countsGroups` / `countsSessions` keys remains deferred.

## Host integration

The plugin registers all packaged dictionaries with the host locale service.
It does **not** call `addLanguage` and does not add a language picker. The host
or a third-party language pack owns the language catalog: when such a pack
activates `ja`, `ko` or another packaged language, the plugin switches
automatically.

## Known limits

- Arabic is the only packaged RTL language. Root `dir`, core list/header/dialog
  styling, menu/dialog viewport bounds and the settings-panel direction are
  covered; the profile popover/preview bounds and direction were exercised by
  the 2026-11-09 all-locale run. Exhaustive drag/resize geometry and every icon
  are not.
- `he`, `fa` and `ur` are not packaged.
- ru/hi/ar narrow-sidebar screenshots cover a 264px-min sidebar (252px content
  width after borders); from `.64` the header title is hidden as a whole at
  264/280/300px (`data-title-collapsed`, no ellipsis), the wrapper's `title` and
  the profile chevron's `aria-label` stay readable, and the full title returns
  from 320px.
- Only English has the default full A+; Japanese has the onboarding fixture;
  all 19 packaged dictionaries have header/dialog/group-menu/settings smoke
  coverage through `.62` (23/23, 2026-11-11, community host).
- `archive.label` is still packaged in all 19 dictionaries but is no longer
  referenced after the view-options popover was split into two labelled
  segments. Removing it would change the 397-key parity count, so it is kept
  for now; this is a resource-only dead key, not a UI regression.
