# dsh-session-grove 0.4.0-beta.62

Group archive, a second view-options tri-state and a recursive structural lock,
plus a smaller QQ-group QR asset. Unreleased `dev` batch — the latest published
release is `0.4.0-beta.61`. This note covers the whole batch: the feature
is a real behavior/contract extension, not an asset-only change.

## Group archive

- `Group.archived` is an additive optional boolean; `DOC_VERSION` stays 1 and
  no migration runs. Missing reads as `false`; `validateDoc` rejects a
  non-boolean value with `group-archived-type:<id>`; the host writes an explicit
  `true|false`. The flag is per profile and never touches the registry.
- `effectiveArchived = own || any archived ancestor`; `archivedBy` is the
  nearest archived ancestor id (self when own-archived) and is derived, never
  persisted. All walks are cycle-safe for corrupt documents.
- A second, independent archive tri-state for groups (`hidden | all | only`,
  storage key `dsh-session-grove.archive.groups.v1`) joins the existing session
  tri-state. `hidden` prunes archived subtrees but keeps live ancestors; `all`
  renders everything; `only` renders `full` (effective archived) groups and
  header-only `pathOnly` ancestors that lead to them, hides ungrouped and shows
  an empty view when no group is archived. Session filtering still applies
  inside rendered groups only.
- Search and header status counters consume the same group visibility
  (`computeGroupVisibility`), and `assigned` is computed from the full document,
  so hidden-group sessions cannot leak into ungrouped. A query that only hits
  hidden content offers an explicit "show archived groups" action instead of
  silently changing the filter.

## Structural lock and invariants

- The whole recursive subtree of an effectively archived group is frozen:
  title, icon, color, `colorHex`, parent, sibling index, `sessionIds` order and
  direct child-group order cannot change; archived groups and groups containing
  archived descendants cannot be moved or deleted; inserting into an archived
  destination, or shifting an archived anchor's sibling index indirectly, is
  rejected.
- The archive switch itself is always legal, never cascades to sessions or child
  groups, and never calls `archiveSession`. Sessions inside an archived
  container can still be opened (when not archived themselves), renamed, toggled
  archived and have their ID copied; drag, reorder, move-to-group and fork are
  disabled with a visible reason.
- The invariant is a strict **before-state** comparison: a group archived before
  the commit may only change its own `archived` flag. `unarchive + edit` must be
  split into two commits; `archive + edit` is legal. Comparisons use normalized
  values (`color`/`colorHex`/icon/`archived === true`), so host normalization
  cannot produce false violations.
- Drag preview and commit share the same predicates (`checkSessionDrop`,
  `checkGroupDrop`/`applyGroupDrop`): slots resolve against the full document
  with stable ids, archived bodies reject without bubbling, no placeholder is
  drawn for an illegal target, partial pruning never allows a drop the commit
  would reject.

## Host and control contract

- `store.commit` reads the current document, inherits a missing inbound
  `archived` by group id (so an old client's full-document write cannot silently
  unarchive a group), validates for write, then applies the before-state
  invariant. A violation returns `kind: 'archive-frozen'` with no write and no
  revision bump; `/commit` maps it to 409
  `{ ok:false, code:'archive-frozen', reason:<op code>, groupId, field }`.
- `store.save()` for a new profile has no current document (missing = `false`)
  and backup restore writes the backup content verbatim; both are explicit
  invariants exceptions and are documented.
- Control API: new `group.archive { groupId, archived }` operation, separate
  from `group.update`; `state.groups[]` exposes `archived`, `effectiveArchived`
  and `archivedBy` (not view-only `pathOnly`). Archive-state conflicts return
  409, schema/type/unknown-field errors stay 422; batches apply in order and
  are re-checked against the original document (`operationIndex: -1` on a
  terminal violation); a same-value `group.archive` is `no-change`.
- UI: two labelled tri-state segments in the view-options popover (kept open
  across picks; Escape/outside click closes), header button mirrors both values
  (`data-filter`/`data-group-filter`), `data-archived`/`data-path-only`/
  `data-contains-archived`/`data-structural-locked` attributes, single-composite
  dimming (nested groups/session rows reset opacity, `pathOnly` stays
  undimmed), archive dialogs/toasts, disabled items with reasons, invisible
  result actions and `archive-frozen` failure mapping.
- UI patch: the archive-group confirmation dialog gained a default-off
  "Don't ask again" checkbox (`dsh-session-grove.archive.confirm-skip.v1`).
  Checking it and completing the archive skips only the confirmation for later
  group archives — the strict commit, guards, success toast and focus handling
  are identical; cancel/failure never persists the choice. "Restore default
  display" (reset layout) resets the opt-out, and the reset row now uses a
  compact circular reset glyph (candidate B) instead of the refresh/X-like
  icon. The group archived lock / contains-archived badges use 16px glyphs,
  aligned with the row action eye icon.
- i18n: 54 keys added to all 19 dictionaries (331 → 385), including the second
  tri-state, archive menu/dialog/drag/toast/empty/search copy, the archive
  confirm opt-out and two plural `search.hidden*` keys; 13 keys are CLDR plural
  objects.

## Compatibility

- Additive contract extension over `DOC_VERSION` 1; the frozen
  `docs/CONTRACTS.md` is not modified. `docs/adr/0004-group-archive-freeze.md`
  records the decision and the "Doc stores no … archive flags" clarification
  (that line is about session flags held by the host, not group flags).
- Old documents: missing `archived` reads as `false`; no reject, no quarantine.
- Old client + new host: the host inherits missing flags from the current doc,
  so state is not silently lost; structural edits to a frozen subtree are
  rejected by the host guard (old clients may show a generic error — accepted
  degradation).
- New client + old host: the field usually survives the whole-document write,
  but the old host neither displays archive state nor enforces the invariant;
  only the client-side mutators guard until the host is upgraded.
- Backup restore may return to a pre-archive state (restore-path exception).
  Downgrading to a host that does not know the field leaves `archived` in the
  JSON, hides the archive UI and skips the lock; re-upgrading restores both
  without migration.

- The QQ group QR asset was replaced: `assets/qrcode-qq-group.jpg` is a real
  480×855 JPEG, **40,272 bytes**, sha256

  `assets/qrcode_1794236242994.jpg` was actually a 1284×2286 PNG misnamed
  `.jpg`, **611,364 bytes**. Actual net reduction: **571,092 bytes** (−93.4%).

  no longer packaged and no manifest, README or code references it.
- The asset swap itself changes no code, API or storage format.
