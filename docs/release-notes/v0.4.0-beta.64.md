# dsh-session-grove 0.4.0-beta.64

One placement policy for every floating panel: the three status popovers, the
view-options popover, the configuration popover, row menus and the drag label now
stay inside the visual viewport at any sidebar width, window size or zoom level,
in both writing directions. This is a `dev` batch for `0.4.0-beta.64` — it is
**not released**: no tag and no GitHub Release exist for it, and the package
version is still `0.4.0-beta.63` until the release step bumps it. The latest
published release is `0.4.0-beta.63` (2026-11-12).

## Shared geometry

- New pure core `src/core/popover-position.js` resolves a floating panel against
  the visual viewport: anchor on a logical inline edge (`inline-end` /
  `inline-start`, mirrored in RTL), flip to the opposite side when the preferred
  side overflows, clamp only as a last resort, and cap the height by the space
  that is actually left below or above the trigger.
- `size` is the **border-box** footprint, so feeding a measured
  `offsetWidth`/`offsetHeight` back into the resolver never grows the panel by
  its own padding or border — that is what makes the two-pass placement
  converge.
- Non-finite, negative or zero viewport values fall back to the 8px inset
  instead of producing NaN coordinates, and a short panel is no longer judged
  "unusable below" by its own capped height.

## Floating-panel controller

- New `src/client/floating-panel.js` (`useFloatingPanel`) measures twice inside
  one layout effect — design constants first, the mounted border box second —
  so the box is final before the first paint and does not visibly jump.
- Writes are convergent: the DOM is touched only when left, top, width or the
  height cap moved by at least 1px, so a resize settles after one write instead
  of ratcheting the panel wider each round.
- Relayout on `window.resize` plus a `ResizeObserver` on the trigger; the height
  cap is re-read on every relayout, so a purely vertical resize still refreshes
  it (`maxHeightCap` also gives a content-sized panel the padded viewport height
  instead of `max-height: 0`).
- I2 self-check: once per open the controller hit-tests the four inset corners
  of the placed panel. If a host `transform`/`filter` re-contains the fixed box
  (which no rect reports), the panel is folded into the nearest clipping
  ancestor and marks itself with `data-fallback="clip"`; the normal path carries
  no such attribute.
- The three status popovers, the view-options popover and the configuration
  popover are now `position: fixed` with `left`/`top`/`width`/`max-height`
  written by the controller. CSS keeps only the border box and the viewport
  min/max fallbacks; the physical `left`/`right` anchors and the RTL physical
  override are deleted (the logical edge is resolved in JS from the panel's
  nearest `[dir]` ancestor).

## Compact header

- `data-narrow` is driven by the measured `.dsg-root` width with a 377/385
  hysteresis (the first frame estimates it as `appliedWidth - 12`), never by
  header-row overflow: the flex row shrinks the title instead of overflowing, so
  an overflow check would never fire.
- `data-title-collapsed` measures the always-laid-out `.dsg-header-title`
  (42px collapse / 50px expand on its usable width, chevron and the 2px/4px
  inline gap subtracted) and hides the whole label below the threshold instead
  of ellipsizing it. Measuring the label itself would read 0 while hidden and
  lock the title away forever.
- Additive attributes only: `data-placement` (actual resolution: a logical
  token, `flipped` or `clamped`), `data-width` (rounded measured root width),
  `data-title-collapsed` and `data-fallback="clip"`. No test id, CSS class or
  control-protocol contract changed, and the document schema is untouched.

## Menus, drag label and focus

- `menuBoxLimits` caps the row menu at `min(360px, 100vw - 16px)` and at the
  space left below its final y, so a pointer-anchored menu scrolls instead of
  running off a narrow or short viewport. The x/y shift clamp keeps its original
  implementation and return shape (only the box math is delegated), and the
  menu keeps its 30px rows with single-line ellipsized labels plus `title`.
- The floating drag label is clamped to the viewport before it is written (8px
  inset, compensating `translate(12px, 10px)`), caps at
  `min(280px, 100vw - 44px)` and ellipsizes in one line. I2 does not apply to a
  pointer-following label.
- All five header triggers (three status buttons, view options, profile
  chevron) return focus to the button when their popover closes, including the
  profile popover whose earlier capture-phase focus was overwritten by the
  browser's default focus handling. The row menu's existing focus return is
  unchanged.

## i18n and compatibility

- **No new i18n keys**: 397 keys in 19 dictionaries are unchanged (no locale
  resource changed in this batch). Long labels reuse the existing copy in a
  `title`, and the header title's wrapper keeps `view.title` while the label is
  hidden, so nothing new needs translating.
- No document schema change: `DOC_VERSION` stays 1, no new fields, no
  migration, no new persisted preference. `lib/client.js` is rebuilt from source
  by `npm run build`.
