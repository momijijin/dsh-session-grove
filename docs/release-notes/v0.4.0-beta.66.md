# dsh-session-grove 0.4.0-beta.66

`0.4.0-beta.66` is the sidebar performance batch. The last published release is
still `v0.4.0-beta.65` (2026-11-13); this batch carries no version tag and no
GitHub Release of its own.

## What this batch does

The batch adds one controlled performance-observation layer and the attribution
data needed to judge the sidebar hot paths from a single NDJSON file:

- `PERF_MEASURE_BUILD` is `true` in `src/shared/constants.js`, so the client
  reporter and the host `/dsh-session-grove/perf` route are **on by default**.
  No setting has to be changed to capture resize / scroll / drag attribution;
  whether the observation layer is kept once the batch wraps up is decided at
  wrap-up (see below).
- The client reporter records `gesture` rows (one per width-resize, scroll,
  session/group drag, dialog move or dialog resize), `window` rows (every
  15 seconds when there is an increment) and `final` rows (page hide/unload).
- Long Animation Frame (LoAF) attribution: where the browser supports the
  `long-animation-frame` entry type, each frame contributes four samples
  (`loafDurationMs`, `loafStyleLayoutMs`, `loafScriptMs`, `loafRenderMs`) and up
  to 20 raw entries per record (`startTime`, `duration`, `blockingDuration`,
  `renderStart`, `styleAndLayoutStart`, and at most three scripts with duration,
  invoker and base file name). Where the entry type is unsupported the existing
  `longtask` duration is kept instead.
- Rows carry counts, durations, viewport/tree sizes, component names and the
  plugin version only — no session ids, titles, group names, text or paths. A
  LoAF script URL is reduced to its base file name before it is recorded.
- The host appends each row as one NDJSON line to
  `<storages>/dsh-session-grove.perf.ndjson` (the plugin storage directory,
  next to the other `dsh-session-grove.*` files).

Nothing else changes: no feature, behavior, visual, locale, public API,
storage-format, test-id or CSS/ARIA contract moves in this batch. Every new
instrumentation call early-returns when capture is disabled, so the disabled
path costs one cached boolean check.

## Turning capture off on the spot

Set the opt-out flag in the client console and reload:

```js
localStorage['dsh-session-grove.perf'] = '0'
```

The reporter stops sending right after the reload. The host route stays
registered, but no new lines are appended because the client no longer posts.

## Keeping or retiring the observation layer

Whether the instrumentation stays after the `.66` batch wraps up is a wrap-up
decision. Setting `PERF_MEASURE_BUILD` to `false` in `src/shared/constants.js`
— the single switch shared by the client reporter and the host route — restores
the historical opt-in path (`globalThis.__DSG_PERF__ === true` or
`localStorage['dsh-session-grove.perf'] = '1'`). No other cleanup step is
needed; the perf file can be left in place or removed by hand at that point.
