# dsh-session-grove 0.4.0-beta.66

`0.4.0-beta.66` is the sidebar performance batch. The last published release is
still `v0.4.0-beta.65` (2026-11-13); this batch carries no version tag and no
GitHub Release of its own.

## What this batch does

The batch keeps the local performance-observation layer that was built to find
the hot paths, but **ships it off**, and lands the plugin-side work the
measurements pointed at. No new feature, locale resource, public API,
control-protocol, storage-format, test-id, CSS or ARIA contract moves in this
batch.

### Capture is off by default — and needs both ends to turn on

- `PERF_MEASURE_BUILD` is `false` in `src/shared/constants.js`, so the release
  build records nothing.
- The client reporter and the host `/dsh-session-grove/perf` route are both
  still shipped; capturing again is a local, **two-end** opt-in:
  - **client**: `localStorage['dsh-session-grove.perf'] = '1'` (or
    `globalThis.__DSG_PERF__ = true`), then reload;
  - **host**: the plugin's `perf` configuration key must also be true, otherwise
    the route rejects the POST with 403 and the client keeps the records queued.
- `localStorage['dsh-session-grove.perf'] = '0'` still force-disables capture
  and wins over both opt-ins.
- With capture off, every instrumentation call early-returns after one cached
  boolean check; the disabled path costs nothing measurable.

When capture is on, rows carry counts, durations, viewport/tree sizes, component
names and the plugin version only — no session ids, titles, group names, text or
paths. Rows are appended to `<storages>/dsh-session-grove.perf.ndjson`; a LoAF
script URL is reduced to its base file name. Gesture rows cover width resize,
scroll, session/group drag, dialog move and dialog resize; long-animation-frame
attribution (with the `longtask` fallback) is included where the browser
supports it.

### Sidebar — three fixes

1. **P2: the width override goes through one CSS custom property.** The
   installed sheet is static (`grid-template-columns: var(--dsg-sidebar-col) …`)
   and each width frame writes only the inline custom property; a drag no
   longer rewrites the stylesheet (`width:styleWrite` went to 0, while
   `width:cssVar` tracks the applied frames). During a width drag the ungrouped
   section also defers its layout measurement and re-measures once after the
   gesture.
2. **Chrome measurement is suspended during a width drag.** The sidebar chrome
   no longer forces a layout read (`.dsg-root` rect + header-title width) per
   frame: the gated callback only marks the pass dirty and keeps `data-narrow`
   live from pure arithmetic on the live preview width, then measures once after
   release. A non-finite live width is skipped and the deferred pass is owed.
3. **The drag line is decoupled from layout.** During a width drag the line
   follows the pointer through `transform: translate3d(...)` in the pointer's
   rAF, without a React render; the width preview updates only the live
   controller (no `setPreferredWidth`), the commit applies the final width
   unconditionally on release, and an adaptive backpressure interval
   (`max(32 ms, 1.5 × EMA of the write-frame cost)`) decides when the layout may
   advance. `width:pointerLagMs` samples the pointer-to-frame lag. The inherent
   cost of the host shell's full-page grid reflow remains; this changes *who
   pays it and when*, not the cost itself.

### Dialogs — two layout fixes, plus per-frame coalescing

- The nested scroll body and the icon grid / dialog list now fill a resized
  dialog (height and width) when `data-positioned="true"`; the real menu keeps
  its 360px cap and unpositioned dialogs keep their previous size.
- Dialog move/resize notifications are coalesced into one `setDialogRect` per
  frame, and `pointerup` cancels the queued frame and applies the release
  position synchronously, so the final geometry is unchanged.
- The scrollbar's scroll/resize/ResizeObserver path is coalesced into one
  recomputation per frame; the mount measurement and the thumb drag stay
  synchronous.

### Drag targets — A (hold) + A2 (speed gate)

- **A**: a new drop target is only committed after it survives a 70 ms hold, so
  crossing a row during a sweep no longer inserts/removes the placeholder on
  every pass; drop/dragend/dragleave still flush the candidate synchronously, so
  the drop always acts on the freshest target.
- **A2**: the hold is skipped when the pointer is aiming — the 100 ms sample
  window's net speed below 0.5 px/ms, or a pause above 100 ms, commits the
  target immediately; a pending hold is upgraded when the last 40 ms of samples
  slow down. A fast sweep keeps the hold, a slow aim is immediate, and a missing
  pointer falls back to the fixed hold.
- A drag start resets the speed window and the dragover dedupe state, so the
  first candidate of a new drag can never be decided by the previous drag's
  motion.

  coverage **95.00–95.01% lines / 86.89–86.92% branches / 91.97% functions**
  (thresholds 92/80/85), `check:ui` **45/45** and `check:release` **PASS**. No
