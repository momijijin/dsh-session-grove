# dsh-session-grove 0.4.0-beta.65

A dialog keyboard-timing fix plus an architecture-debt cleanup batch. The latest
published release is `0.4.0-beta.64` (2026-11-12); `0.4.0-beta.65` is a `dev`
batch that is **not tagged or published** (local batch date 2026-11-13).

No public API, storage format, locale resource or UX contract changed:
`DOC_VERSION` stays 1, the control protocol and the 21-key host integration
surface are unchanged, the 397 keys in 19 dictionaries are untouched, and the
test ids, CSS classes and ARIA wiring are the same. `lib/client.js` is rebuilt
from source by `npm run build` and carries the `.65` version stamp.

## Dialog keyboard timing

- Failure symptom: the isolated suite could fail at
  `keyboard dialog move did not move right` right after the dialog opened. The
  arrow key was consumed but the dialog did not move, or focus had already left
  the titlebar/resizer, so the key handler never ran.
- Two candidates were identified and both are addressed:
  1. **Focus loss before the arrow key.** The dialog seeded focus through two
     paths — the `[dialog]` effect and a duplicate 10ms input-focus timer in the
     seed effect — so a late timer could steal focus from the titlebar/resizer
     the test had just focused.
  2. **Rect timing before the geometry lands.** `dialogRectRef.current` is only
     filled after the first geometry measurement; a keyboard gesture arriving
     before that read `null` and did nothing even though the dialog was visible
     and marked positioned.
- e2e (`e2e/isolated.spec.mjs`): the dialog now waits for
  `data-positioned="true"` before the keyboard section, and the new local
  `focusAndSettle` helper focuses the titlebar/resizer, settles 150ms, retries
  once, and asserts `document.activeElement`. A failure reports the
  `activeElement` test id instead of a bare "did not move" line.
- Plugin focus guard (`src/client/dialog-host.js`): the duplicate 10ms seed
  timer is gone; the single deferred focus runs through
  `shouldFocusDialogTarget(activeElement, dialogElement)`, which skips the focus
  write when focus is already on a dialog descendant (and still focuses when
  focus is `null`, `body`, an outside element or the dialog itself). Inline
  error re-dispatches therefore no longer pull focus out of an input.
- Rect fallback (`src/client/dialog-geometry.js` + `dialog-host.js`):
  `dialogRectFromElement` adapts a measured rect but rejects non-finite or
  non-positive sizes; `resolveDialogRect` prefers the persisted/ref rect and
  otherwise clamps the measured one. `currentDialogRect()` feeds the gesture and
  the keyboard move/resize paths, so the first arrow key works before the
  geometry effect has stored a rect. The fallback is not persisted: once a rect
  exists, the existing keyup `persistDialogRect()` saves it as before.

## Module split

- `src/client/plugin-host.js` **312 lines** (was 961 before the split): mount
  shell only — slot lifecycle, width/layout, workspace chrome, settings/styles
  installation, store subscriptions, window/document listeners, mount/dispose
  and the 21-key return surface.
- `src/client/plugin-host-commands.js` **682 lines** (new): the host command
  layer — `createActions` bridge, archive/session actions, new-session follow,
  dialog commands and `confirmDialog`, filter/epoch and the follow guard. The
  dependency is one-way: shell → commands → core/shared/client pure modules;
  commands import no DSH package (clipboard is injected by the shell).
- `src/client/dialog-host.js` **710 lines** (was 976): modal shell — effects,
  geometry, focus guard, Tab/Escape, gestures, keyboard handling, body
  assembly, footer and `shouldFocusDialogTarget`.
- `src/client/dialog-bodies.js` **315 lines** (new): the group/session dialog
  bodies (`delete-group`, `archive-group`, `archive-running`, `move-session`,
  `move-group`, `icon`, `group-color`), with `DIALOG_KEYS` /
  `DESTINATION_REASON_KEYS` moved alongside the body semantics and imported
  one-way by the shell.

## Deduplicated helpers

- `src/host/atomic-write.js` (69 lines): the shared helper primitives only —
  the retry loop and retryable codes, `pathExists`, the best-effort directory
  fsync, the quarantine timestamp and the temporary-path builder. The
  temp → fsync → `.bak` → rename → directory-fsync write sequence itself still
  lives in `src/host/store.js` and `src/host/profile-registry.js`; only the
  helper primitives were deduplicated.
- `src/host/file-lock.js` (149 lines): cross-process `.lock` acquisition,
  stale-lock recovery and token-checked release are shared by the store and the
  registry; the error code and busy message are injected by each caller. The
  in-process `enqueue` promise tail stays in each module.
- `sessionContainer` (`src/client/actions.js`): one tree-container lookup reused
  by the command layer; the duplicate lookup in `plugin-host-commands.js` is
  gone.
- Registry classifier (`src/host/profile-registry.js`): one classifier now
  drives the registry diagnostics and `src/host/storage-health.js`, so the
  doctor report cannot drift from the registry's own verdict.
- `MAX_PROFILES`: `state.js` and `components-profile-dialogs.js` use the shared
  constant directly; the `DEFAULT_PROFILE_LIMIT` alias (and its dead export) is
  removed.

## Boundary guards

- Import-cycle guard in `tests/core/dependency-direction.test.js`: the relative
  import graph is built from the same `specifiers`/`resolveTarget` helpers and
  DFS-checked; the current 116 source modules / 335 adjacency edges resolve to
  **0 cycles**, and a negative fixture proves the detector can see a cycle.
- The 21-key `createHostIntegration` return contract is asserted from the shell
  source text, so the split cannot silently drop or add a key.
- `createHostCommands` exposes exactly the **17 documented keys**, asserted by
  `tests/client/plugin-host-commands.test.js`.
- `uiModules` is **28** in `tests/ui/ui-runtime.spec.mjs`; the two extracted
  modules are part of the module-load smoke and the source-text assertions were
  moved to the new files in the same commits (no stale-file assertions).
