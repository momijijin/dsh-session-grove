# dsh-session-grove 0.4.0-beta.61

Pure module refactor and boundary-test hardening. This batch does not change the
public API, storage format, locale resources or visible UX (one incidental
failed-unarchive toast copy fix is recorded below); it only splits oversized
modules, removes duplicated definitions and adds tests. Unreleased `dev` batch —
the latest published release remains `0.4.0-beta.60`.

## Changed

- Client composition root: `src/client/plugin.js` (1300 lines) is now a
  composition root (about 400 lines). Document reads/serialized commits live in
  `src/client/plugin-document.js`, the profile domain (list refresh, preview,
  activation, create/rename/archive, passive switch notice) in
  `src/client/plugin-profiles.js`, and slot/host actions/dialog orchestration and
  mount wiring in `src/client/plugin-host.js`. Mutable state follows the
  controller that writes it; dependency direction is
  `document ← profiles ← host`; the injected runtime bridge keeps every key it
  had before.
- Profile UI: `src/client/components-profiles.js` was split into
  `profile-switcher.js` (header chevron, popover, recovery strip),
  `profile-preview.js` (diff body and preview footer) and `profile-switch.js`
  (preview → activate → undo/recover flow); the preview-preference storage moved
  to `profile-storage.js`. The module graph is acyclic: the two preview
  predicates are defined once in `profile-switch.js` and re-exported from
  `profile-preview.js` so both public module surfaces keep their names.
- Profile dialogs: the profile half of `src/client/dialog-host.js` moved to
  `src/client/dialog-profile.js` (save-as/rename/manage/archive bodies,
  client-first name validation, footer actions and write submission). The shell
  only dispatches by `dialog.kind` and keeps the generic modal chrome
  (focus trap, geometry, keyboard, close/Escape); `DialogHost` props are
  unchanged and group/session dialog bodies stay in the shell.
- Host contract: `src/host/route-contract.js` was split into
  `src/host/http/wire.js` (HTTP primitives and request-body parsing, now also
  owning the shared `readJsonBody` used by the profile routes),
  `src/host/http/respond.js` (frozen response shapes) and
  `src/host/profile-policy.js` (profile-scoped plan hash, control-target
  resolution, doctor storage report, preview token and display-name policy). The
  legacy single-store adapter moved to `src/host/legacy-profile-manager.js`; the
  `routes.js` re-export bridge was removed.
- View state: `src/client/state.js` is now a barrel over
  `src/client/state/persistence.js` (localStorage keys, safe accessor, read/write
  and collapsed-table normalization) and `src/client/state/external-change.js`
  (SSE revision/`active` routing); `createStore` stays in `state.js` and the
  existing importers keep importing from it unchanged.
- Deduplication: `src/shared/profile-limits.js` is the single definition of
  `MAX_PROFILES` (20) and `MAX_PROFILE_NAME` (40) — `src/host/constants.js`
  re-exports both for existing host importers, and the four client fallback
  literals now import the shared constant (`PROFILE_NAME_MAX` remains as an
  exported alias). `src/shared/profile-name.js` holds the shared trimmed
  display-name validation and case-insensitive duplicate check used by both
  `src/host/profile-registry.js` and `src/host/profile-policy.js`. HTTP
  request-body primitives and validators are centralized in `host/http/wire.js`:
  the profile routes use the shared `readJsonBody` (moved out of
  `profile-routes.js`), while `/commit`, `/diagnostics` and the control routes
  keep their own bounded readers with unchanged error codes and copy.
- CSS split (SPEC §7.4 conditional item): **closed without splitting**.
  `src/client/css.js` is byte-identical to `.60` (68368 bytes,
  sha256 `c47bd3bec5982f293b492aeca325e9e8127f189d67dd1257f3d8e81f7cb55c18`).
  The six proposed domains are not contiguous in the current file (the
  `profile` slice also contains the onboarding/empty-state rules; the dialog
  slice also contains the running-session action, toast, rail, settings form,
  flat fallback and diagnostics HUD), and concatenating the domains in the
  SPEC-listed order would change the byte sequence (reordered-join sha256
  `732e9ea1513ec34e7a73b97ab197b735ee6503e22cba2d6bbbb41753c478588b` differs
  from the baseline). A truly single-responsibility split would need about 11
  contiguous fragments, which is not worth the extra files; rule order is
  unchanged.

## Incidental fix (not a feature)

- `createActions` is now created after mount, when the locale runtime has
  installed the real translator. It used to be created at `createPlugin()`
  module-load time, when `t` was still the identity `(key) => key`. The one
  visible effect: a failed session unarchive toast now shows the translated
  `toast.unarchiveFailed` copy instead of the raw i18n key. The rename failure
  path is unchanged (its visible toast already came from the dialog handler with
  the mounted translator). This is an incidental correction of an existing
  wrong message, not a new feature, and no API/UX contract changed.

## CI hardening

- Pinned the two third-party GitHub Actions to immutable commit SHAs in both
  `.github/workflows/ci.yml` and `.github/workflows/release.yml`:
  `actions/checkout@fbc6f3992d24b796d5a048ff273f7fcc4a7b6c09 # v5.1.0` and
  `actions/setup-node@a0853c24544627f65ddf259abe73b1d18a591444 # v5.0.0`, so a
  moved or re-tagged action cannot change what CI or the release workflow runs.
- Added a production dependency audit gate
  (`npm audit --omit=dev --audit-level=high`, high/critical only): a dedicated
  `ubuntu-24.04`-only CI step immediately after `npm ci`, and the first command
  of the release `Verify release` block. Scope is runtime dependencies only; the
  install step keeps `--no-audit --no-fund`.
- Local audit: `found 0 vulnerabilities` (0 info/low/moderate/high/critical); a
  first attempt hit a transient `registry.npmjs.org` TLS disconnect and the
  retry passed. This hardening changes no runtime, API, storage or locale
  behavior.

## Docs & repo hygiene

- Removed maintainer-machine absolute paths from the public docs: the
  `docs/TEST-RESULTS.md` run instructions now use `cd <repo-path>` and the
  `docs/archive/README.md` archive pointers use `%USERPROFILE%\Projects\...`
  instead of `C:\Users\<maintainer>\...` (generic placeholders only; no
  behavior change).
- `.gitignore` (Release artifacts) now also ignores `SHA256SUMS` and `*.sha256`
  (generated locally by the release workflow) and documents that local
  packaging must write into a temp directory — a tarball left in the repository
  root is historical leftover and is never tracked.
- Both READMEs' development checklist now uses
  `npm pack --pack-destination "$env:TEMP\dsh-grove-pack"`, with a note that
  official artifacts come from the tag-triggered release workflow in CI while
  the local package is for self-testing only (verify the manifest /
  `package.json` version before installing). Stale dev-tree numbers were
  refreshed: 699 → 726 unit/contract tests, 21 → 24 client modules, and
  coverage about 94% lines / 85% branches / 90% functions; the historical `.60`
  release-validation paragraphs keep their 699 figure because they describe the
  published `.60` evidence.
